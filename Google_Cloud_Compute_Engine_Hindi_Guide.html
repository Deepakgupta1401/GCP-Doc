क्यों?

Frontend और backend के identical instances को group के रूप में manage करें।

✓
Checkpoint

Cloud Shell
gcloud compute instance-groups managed create fancy-fe-mig \
  --zone=ZONE --base-instance-name=fancy-fe --size=2 --template=fancy-fe

gcloud compute instance-groups managed create fancy-be-mig \
  --zone=ZONE --base-instance-name=fancy-be --size=2 --template=fancy-be

  --zone=ZONE --named-ports=frontend:8080
gcloud compute instance-groups set-named-ports fancy-be-mig \

STEP 13

Autohealing Configure करें

Application unhealthy होने पर MIG failed VM को repair या recreate कर सके।

क्या करना है?

  1. Frontend health check

    Port 8080 response check।

  2. Backend health check

    /api/orders path और port 8081 check।

  3. Probe firewall allow करें

    Google health checker IP ranges को access दें।

  4. Checks MIGs पर apply करें

    300-second initial delay with conservative policy।

क्यों?

Application unhealthy होने पर MIG failed VM को repair या recreate कर सके।

✓
Checkpoint

3 consecutive unhealthy results replacement trigger कर सकते हैं।

Cloud Shell
gcloud compute health-checks create http fancy-fe-hc \
  --port=8080 --check-interval=30s --healthy-threshold=1 \
  --timeout=10s --unhealthy-threshold=3

gcloud compute health-checks create http fancy-be-hc \
  --port=8081 --request-path=/api/orders --check-interval=30s \
  --healthy-threshold=1 --timeout=10s --unhealthy-threshold=3

gcloud compute firewall-rules create allow-health-check \
  --allow=tcp:8080-8081 \
  --source-ranges=130.211.0.0/22,35.191.0.0/16 --network=default

STEP 14

HTTP Load Balancer बनाएँ

एक public IP से frontend और backend API paths को सही services पर route करें।

क्या करना है?

  1. LB health checks बनाएँ

    Frontend, Orders और Products के लिए अलग checks।

  2. Backend services बनाएँ

    Health checks और named ports associate करें।

  3. MIGs attach करें

    Frontend MIG frontend service में, backend MIG API services में।

  4. URL map बनाएँ

    / frontend; /api/orders और /api/products backend।

  5. Proxy और forwarding rule

    Public port 80 traffic को URL map से जोड़ें।

क्यों?

एक public IP से frontend और backend API paths को सही services पर route करें।

✓
Checkpoint

Production में HTTP के बजाय HTTPS और certificate use करें।

Cloud Shell
gcloud compute url-maps create fancy-map \
  --default-service=fancy-fe-frontend

gcloud compute url-maps add-path-matcher fancy-map \
  --default-service=fancy-fe-frontend \
  --path-matcher-name=orders \
  --path-rules="/api/orders=fancy-be-orders,/api/products=fancy-be-products"

gcloud compute target-http-proxies create fancy-proxy --url-map=fancy-map
gcloud compute forwarding-rules create fancy-http-rule \
  --global --target-http-proxy=fancy-proxy --ports=80

STEP 18

Autohealing Failure Test

Service को intentionally stop करके देखें कि MIG repair operation करता है।

क्या करना है?

  1. MIG instance name निकालें

    Frontend group की VM चुनें।

  2. SSH करें

    Selected instance में connect करें।

  3. Node application stop करें

    Supervisor और Node process रोकें।

  4. Repair monitor करें

    compute.instances.repair operation DONE होना चाहिए।

क्यों?

Service को intentionally stop करके देखें कि MIG repair operation करता है।

✓
Checkpoint

Expected repair type: compute.instances.repair.recreateInstance

Cloud Shell
gcloud compute instance-groups list-instances fancy-fe-mig --zone=ZONE
gcloud compute ssh INSTANCE_NAME --zone=ZONE

sudo supervisorctl stop nodeapp; sudo killall node
exit

watch -n 2 gcloud compute operations list \
  --filter='operationType~compute.instances.repair.*'

Quick Glossary

Compute Engine
Application चलाने वाली virtual machine service.
Instance Template
VM configuration का reusable blueprint.
MIG
Identical VMs का managed group.
Health Check
Service response और availability verify करता है.
Autohealing
Unhealthy VM को repair या recreate करता है.
Load Balancer
Traffic को सही backend service तक भेजता है.
Autoscaling
Load के अनुसार instance count adjust करता है.
Cloud CDN
Cacheable content को edge cache से serve करता है.
